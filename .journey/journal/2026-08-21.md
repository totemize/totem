# 2026-08-21

## Waveshare V4 contrast and flash correction

Compared Totem's V4 partial-refresh sequence directly with Pwnagotchi commit
`6e31b26` on the only authorized display host, metot. Pwnagotchi defaults to
event-driven UI refresh, establishes one full base image, then pulses reset for
1 ms and writes only the new `0x24` plane for each `0xFF` partial update. Totem
was instead retaining reset across a burst, rewriting the prior frame to
`0x26`, and promoting every twentieth requested partial update to a disruptive
full refresh.

A deterministic camera-visible test alternated filled and outlined blocks for
41 updates under each driver sequence. Both paths took about 26 seconds. The
old Totem sequence left the nominally white block gray and fine text weak. In
the same raw camera crop, the median white-minus-black luminance separation was
36 levels. The Pwnagotchi sequence produced a clean white field, dense black,
and readable fine text, with 47 levels of separation (31% larger).

The V4 production driver now pulses reset before every partial frame and writes
only `0x24`. A full refresh still seeds both RAM planes when controller state is
unknown, and any I/O failure still invalidates the baseline. Scheduled full
promotion is disabled by default with `TOTEM_EINK_FULL_REFRESH_EVERY=0`; a
positive deployment value remains available for panels that need an explicit
cadence. Metot's converged Ansible inventory pins `0`.

Deployed the content-addressed Python release only to metot. Ansible completed
with `ok=105 changed=12 failed=0 unreachable=0`, and all five services plus SPI,
I2C, UPS, relay, control-plane, and challenge checks passed. A production-path
stress run then completed 201 partial updates in 127.036 seconds without a
full-panel flash. The final raw camera crop retained 49 luminance levels of
white/black separation, slightly above the 47-level result after 41 updates,
so contrast did not decay over the run. The screen and device-manager services
were restored active with cadence `0`; the live Totem face, rules, lightning
badge, and footer were camera-readable.

Local gates: 217 Python tests passed with 5 hardware-only skips; changed Python
files passed Black; compileall, `git diff --check`, and Ansible syntax check
passed. The `spec/` tree was not modified.

After formatting the manager, a final metot-only converge installed exact
release `sha256-bfdbe1144294204abab9cae4640103c8763635cb228b37b6619b635f04e44f11`.
It completed at `ok=105 changed=9 failed=0 unreachable=0`; all verifier gates
passed and both display services were active.

inside that choice. A higher-priority scene preempts the current motion, and a
candidate animation is keyed to its encounter, plays the blush/wink sequence
once, then holds the final blush until that encounter changes.

## State-specific word-reveal captions

Added a presentation-only caption animator on top of the authoritative runtime
scene projection. Each of the 13 scenes owns exactly ten approved phrases. A
chooser is injected for deterministic tests, selects once per genuine scene
admission, excludes that scene's immediately previous phrase, and keeps the
selection stable across face frames, polling, SSE wake-ups, charging reactions,
and display retries. Captions never participate in scene priority, dwell,
encounter identity, or one-shot delivery.

The selected phrase begins at its first word and accumulates one word at a time
near the 1.2-second target. Caption and face deadlines are independent and the
runtime wakes for whichever becomes due first. Transfer-aware scheduling gives
the initial full-refresh prefix a readable settled hold; later prefixes request
partial refresh without changing the face step. A higher-priority authoritative
scene still preempts both animations immediately.

Reserved a fixed 12-pixel caption band between the character and footer, with a
three-pixel clear gap above the unchanged footer rule. Every approved phrase
fits on one line in the 9-pixel bold font. Each progressive prefix is anchored
at the final phrase's centered origin, so existing words do not jump. The
renderer rejects missing glyphs, clipping, or band violations. The deterministic
`totem-screen proof-captions` command renders a 229-frame mode-1 atlas covering
all 130 complete captions, representative prefixes for every scene, and every
face sequence without issuing a long physical replay.

Local verification passed all 261 Python tests with five hardware-only skips,

code changed and the `spec/` tree remained untouched.

an empty driver selection, auto-detected the legacy 3.7-inch default, and the

freshly enabled screen always talks to the new release and environment. The
failed attempt stopped at the display gate; no false-success verification was
possible.
