## motown fips bring-up (aarch64)

Built fips from `references/fips` HEAD `23ec0a7` for motown — same
commit as totem's running binary (`fips 0.5.0-dev rev 23ec0a7b81`).

### Build recipe: aarch64 static musl cross (docker)

Ladder notes, in order tried:

1. Upstream release artifacts are for tagged releases only — our mesh
   runs the dev checkout; mixing versions in a mesh is a gamble. Build
   it ourselves.
2. **gnu target blocked**: BLE transport auto-enables on non-musl
   linux (`build.rs` `bluer_available` — no opt-out env/feature), and
   `libdbus-sys` refuses to cross-compile without a target pkg-config
   setup (multiarch `libdbus-1-dev:arm64` would be needed). Musl it is
   — same posture as totem: static, BLE off, no dbus linkage.
3. Working recipe (debian:12 container, host-arch, ~2 min build after
   deps):
   - apt: `libclang-dev` (rustables/bindgen), `build-essential`
     (build scripts are host-compiled — forgetting this fails on
     `serde`'s build script), `pkg-config`, `wget`
   - musl.cc `aarch64-linux-musl-cross.tgz` → `/opt/cross`
   - `rustup target add aarch64-unknown-linux-musl`
   - `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_MUSL_LINKER=/opt/cross/bin/aarch64-linux-musl-gcc`,
     same for `CC_aarch64_*`/`AR_aarch64_*`
   - **`BINDGEN_EXTRA_CLANG_ARGS_aarch64_unknown_linux_musl="--sysroot=/opt/cross/aarch64-linux-musl"`**
     — without it rustables' bindgen dies on `asm/types.h not found`
     (no target headers on the include path)
   - `cargo build --release --locked --target aarch64-unknown-linux-musl`
   - Output: static aarch64 ELFs (fips, fipsctl, fipstop, fips-gateway)

## motown strfry bring-up (aarch64)

Goal: same setup as totem. Source of truth: totem's own deploy —
`~/src/strfry` (no .git), `~/strfry-deploy/` bundle, unit + config.
Key discovery: totem's strfry is **not stock** — it has `mesh` commands
(router/stream/sync) that upstream master lacks. It's the `router`
branch (`5e81e24`) of `references/strfry` — same commit as metot's
lineage. Per the boss: "it's patched for 32 bits, but aside from that
it's just strfry" — the armv6 build needed patches, aarch64 builds
stock.

### Build recipe: `router` branch for aarch64 (docker, emulated)

`docker run --privileged --rm tonistiigi/binfmt --install arm64` first
(reset by reboots), then in an `alpine:3.18 --platform linux/arm64`
container with the Dockerfile's deps:

- **perl deps**: `perl-template-toolkit perl-yaml` (golpe codegen), and
  `Regexp::Grammars` — pure-perl, **not in 3.18**: extract
  `Regexp/Grammars.pm` from an alpine:3.22 container and drop into
  `/usr/share/perl5/vendor_perl/Regexp/` in the builder.
- **flatbuffers must be 23** (generated headers static_assert the major
  version): that pins alpine 3.18 for building (3.22 ships 25).
- Build tree: worktree copy with all `.git` dirs stripped (git
  safe-directory + worktree metadata live outside the mount — simplest
  to remove git entirely; `make setup-golpe` only checks submodule
  presence).
- `make -j4` → 123 MB with debug_info; strip **inside** the container
  (host binutils is x86-only) → 5.1 MB.
- Full emulated build ≈ 6 min wall.

### Deploy (mirrors totem exactly)

Runtime tree = alpine:3.18 aarch64 minirootfs exported from a container
after `apk add lmdb flatbuffers libsecp256k1 libb2 zstd libressl`
(same .so set as totem's `/opt/strfry`). Layout: `/opt/strfry/{bin,lib,
usr/lib,etc/apk}`, config `/etc/strfry.conf` (totem's verbatim —
`bind = "::"` already set), unit `/etc/systemd/system/strfry.service`
with the loader path swapped to `ld-musl-aarch64.so.1`, system user
`strfry`, `install -d -m 750 -o strfry -g strfry /var/lib/strfry`,
`systemctl enable --now strfry`.

Verified: `active`, listening `[::]:7777`; NIP-11 from totem over the
mesh (fd71::… addr) ✓; NIP-11 from host over LAN IPv4 ✓ (`motown.local`
from the host picked a bad AAAA — use the IP or `.fips` name); `mesh`
subcommands present ✓. Both test units now run identical stacks:
fips @ 23ec0a7 + strfry router-branch.

Build artifacts kept under `/var/tmp/strfry-src` (source+log) — /tmp
is wiped on reboot (lost the first attempt mid-build).
