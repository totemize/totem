## E-ink Rev 2.1 compatibility and final render

Resumed the Waveshare 2.13-inch display work after the Pi Zero returned
online. The user supplied decisive control evidence: the same assembled
Pi/HAT/panel refreshes successfully when booted from a Pwnagotchi SD card.
That rules out HAT/FPC seating and panel failure.

Compared Totem's V2 transport with Pwnagotchi's current `waveshare_2`
implementation. Pwnagotchi configures GPIO24/BUSY with an internal pull-down
and does not require observing a BUSY leading edge before accepting a V2
refresh. Totem previously used no pull resistor and made that leading edge a
hard requirement. On this Rev 2.1 HAT, GPIO24 remains electrically floating
at idle (it follows both software pull-up and pull-down) and no leading edge
is visible even though the display itself is known to work.

Changes:

- bias active-high BUSY low, matching Waveshare/Pwnagotchi Raspberry Pi
  transport behavior;
- make the V2/Rev 2.1 update path wait on BUSY if asserted without requiring
  the leading edge;
- keep the controller powered for a four-second fallback refresh window
  before callers may put it to sleep;
- add contract coverage for the pull-down and V2 behavior.

Verification:

- full local suite: 74 passed, 4 hardware-marked tests skipped;
- deployed the changed base and V2 drivers to `/opt/totem`;
- invoked `examples/display_text.py` through
  `DisplayManager(driver_name="waveshare_2in13_v2")` on real SPI with the
  exact payload `hello world\n<3 totem`;
- initialization, framebuffer transfer, protected refresh interval, sleep,
  and cleanup all completed with exit status 0.

### Build recipe: aarch64 static musl cross (docker)

Ladder notes, in order tried:

1. Upstream release artifacts are for tagged releases only — our mesh
   runs the dev checkout; mixing versions in a mesh is a gamble. Build
   it ourselves.
2. **gnu target blocked**: BLE transport auto-enables on non-musl
   linux (`build.rs` `bluer_available` — no opt-out env/feature), and
   `libdbus-sys` refuses to cross-compile without a target pkg-config
   setup (multiarch `libdbus-1-dev:arm64` would be needed). Musl it is
   — same posture as totem: static, BLE off, no dbus linkage.
3. Working recipe (debian:12 container, host-arch, ~2 min build after
   deps):
   - apt: `libclang-dev` (rustables/bindgen), `build-essential`
     (build scripts are host-compiled — forgetting this fails on
     `serde`'s build script), `pkg-config`, `wget`
   - musl.cc `aarch64-linux-musl-cross.tgz` → `/opt/cross`
   - `rustup target add aarch64-unknown-linux-musl`
   - `CARGO_TARGET_AARCH64_UNKNOWN_LINUX_MUSL_LINKER=/opt/cross/bin/aarch64-linux-musl-gcc`,
     same for `CC_aarch64_*`/`AR_aarch64_*`
   - **`BINDGEN_EXTRA_CLANG_ARGS_aarch64_unknown_linux_musl="--sysroot=/opt/cross/aarch64-linux-musl"`**
     — without it rustables' bindgen dies on `asm/types.h not found`
     (no target headers on the include path)
   - `cargo build --release --locked --target aarch64-unknown-linux-musl`
   - Output: static aarch64 ELFs (fips, fipsctl, fipstop, fips-gateway)

## totemd: signed challenge (totem ↔ motown scope)

Scope constraint from operator: metot is in parallel peripheral work. No SSH,

### Protocol and privilege decisions

- Adopted core `nostr 0.45.3` (`std` + `os-rng`), not `nostr-sdk`: canonical
  event ID, Schnorr signing/verification, NIP-19 parsing. Removed temporary
  direct bech32. The credential read buffer is `Zeroizing`; `nostr::Keys`
  zeroizes its secret on drop.
- Kept `totemd.service` as `User=totem`. systemd 257 `LoadCredential=` reads
  `/etc/fips/fips.key` (source stays root:root 0600) and exposes a private
  read-only credential. Verified first with transient units on totem+motown,
  then live (`User=totem`, `NoNewPrivileges=yes`, source mode still 600).
- No wall-clock acceptance window. Offline Pis cannot assume RTC/NTP after a
  cold boot; a fresh random 128-bit nonce, used for one request then discarded,
  supplies replay resistance. A test signs at `created_at=1` and still proves.
- Responder signs exact kind 27235 / empty content / nonce + endpoint URL + GET
  tags; strict verifier checks event ID, Schnorr signature, FIPS npub match,
  exact shape, and all bindings. Response is `Cache-Control: no-store`.
- Guest-reachable signing is capped by a global 8-signature/second burst
  bucket. This admits simultaneous legitimate peers while bounding armv6 work;
  per-source buckets are deferred unless measured guest abuse causes starvation.
- Recognition is a current-encounter set: successful proof pushes
  `totem.recognized` once; FIPS `gone` clears it. Each challenge captures the
  peer's `first_seen` encounter token, so a slow proof cannot cross a rapid
  disconnect/reconnect. NIP-11 candidate caching remains separate and survives
  encounters for the daemon lifetime.

### Build and control surface

The secp256k1 C build did not need downloaded musl.cc toolchains. Existing
Clang works with its builtin freestanding headers; `.cargo/clang-musl` adds
ARMv6 hard-float/VFPv2 flags and Cargo still links with `rust-lld`. Verified
ELF attributes: ARM EABI5, CPU v6, VFPv2, VFP-register ABI; aarch64 static too.

## Waveshare UPS HAT (C) driver

board exposes an INA219 monitor at I2C address `0x43`; its official reference

## Totem state catalog for interactive display work

Enumerated the device's state space from the current screen, hardware API,
totemd, systemd, and numbered specs in `docs/reference/state-model.md`. The
central design decision is that Totem state is a product of orthogonal axes,
not one flat enum: lifecycle, service/driver health, host and power health,
radio/mesh, per-peer encounter and recognition, persistent relationship,
per-encounter sync, relay/storage, and human activity can change
independently.

The catalog separates observable wire values from code/spec vocabulary that
is not wired, display-derived states, and genuine signal gaps. Current display
work can truthfully use boot progress, mesh health, peer
seen/candidate/recognized/gone, five terminal/active sync values, and UPS
telemetry. New-vs-returning peers, failed challenges, friendship approval,
relay event deltas, storage pressure, post-boot service degradation, host
thermal/resource health, and shutdown intent need new authority before the
screen should claim them.

The proposed presentation model selects a base scene, transient activity, and
persistent badges with explicit arbitration and e-ink coalescing rules. This
preserves simultaneous facts such as “syncing while charging with a degraded
optional service” without inventing compound enum values.

tests passed; 59 focused Python screen, driver, API, and UPS tests passed in a
temporary virtual environment; `git diff --check` passed. Live read-only bench
sampling was attempted but SSH host-key/user configuration in this shell did
