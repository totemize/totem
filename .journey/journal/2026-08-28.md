# 2026-08-28

## Microduck architecture study

Studied `references/microduck` @ `590b986` (Pollen Robotics' biped robot,
Rust, ~90k lines, 942 tests) as an architecture reference for totem's early
stage. Two passes: design docs first (`docs/design/architecture.md`,
`updater-design.md`, `robotd-design.md`, `restart-order.md`), then the code
(`duck-ipc-proto`, `updater` engine/ipc/faults/reconcile, `robotd`
loop/intents/chorale, `duck-control/safety`, `configd/store`, `btd`
route/session, `xtask`, `test-support`, CI).

Findings distilled into **`references/design/microduck-lessons.md`** — the
durable reference with a status-tracked borrow list (B1–B9). Headlines:

- **Compile-enforced invariants** ("make the broken state unrepresentable"):
  exhaustive-match authz tables, single write handles, capability separation
  via dependency choice (`minisign` vs `minisign-verify`).
- **Recovery-path invariant**: their whole service split exists so config,
  BLE, and the updater stay useful when the core is dead. We have the
  property de facto (fips + strfry independent of totemd) but never wrote it
  down — spec 10 candidate.
- **Swapped releases, never patched**: versioned dirs + atomic `current`
  symlink + health gate + rollback; "everything outside `releases/<ver>/`
  survives update and rollback." Borrowable as flash.sh layout without their
  18k-line engine.
- **Decoder-is-the-gate version discipline**: exact-match handshake gates
  were wrong for them (16 protocol versions of experience); unknown params
  members refuse by name instead.
- **Mixed-version mesh**: their "every binary comes from one release"
  assumption is false on our mesh — degradation ("keep listening rather than
  joining") and deterministic leadership ("lower id conducts") patterns from
  their chorale apply to spec 03.
- New open question banked for spec 09: signed releases propagated over the
  mesh via NIP-77 encounter sync — the sneakernet story applied to the fleet.

Decisions: document in `references/design/`, not spec/ yet — borrows B1–B8
are listed with effort and graduate into specs when done. Decided against:
seven-daemon split, their updater engine, closed owner model, unix-socket
bus (our HTTP/SSE bus stays — different threat model, NAP alignment).
